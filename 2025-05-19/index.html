AI를 활용하여 깃허브 블로그 심폐소생술 하기

AI기타·2026.05.19.

안녕하세요. 백만년만에 깃허브 블로그를 활성화하기 위해 글을 쓰기 시작했습니다. 이전까지 저의 깃허브 블로그는 인프런의 React 기반 Gatsby로 기술 블로그 개발하기 강의를 토대로 작성한 블로그였는데요, 실질적으로 개발과 관련된 내용을 적기 보단, 에세이형식으로 글을 작성했었습니다. 사실 에세이라기 보단 감정일기와 다르지 않았습니다.

전에 향로님의 글을 읽던 중, 일기나 블로그를 적을 떄, 부정적인 감정을 일부로라도 감추는 것이 추후에 글을 읽을 때 도움이 된다는 내용이 있었는데요. 제가 전에 적어놓은 일기들도 부정적인 내용이 가득해 정리하게 되었습니다. 그 밖에도, 향로님의 글들을 읽을 때마다 공감되는 부분이 많은데, 개발자 취준생으로서 고민인 부분들을 이미 향로님이 이전의 글들로 풀어놓으셔서 마음 잡는데 도움이 많이 되었습니다.

그런 일기형식의 내용을 정리하고 개발 블로그를 깃허브를 택한 이유는, 모두가 느끼시는 AI의 발전인 것 같습니다. 이전에 Gatsby를 활용하여 개발하였으나, 프론트 지식이 충분하지 않아, 강의 수강 이후의 업데이트는 엄두에 두지 못하고 md파일로 글만 작성했으나, 개발하면서 마주치는 문제와 해결과정, 학습한 내용들을 실질적으로 AI를 사용하지 않은 글로서 작성하고자 깃허브 블로그를 쓰게 되었습니다.

Github 블로그를 사용하는 이유

개발 블로그를 쓰기에는 티스토리, Velog, medium등 다양한 플랫폼이 존재합니다. 기존에 티스토리를 사용하려고 몇번의 글 작성을 진행했었는데, 마크다운 형식으로 작성하지 않을 때 매번 원하는 형식이나 기호를 수동으로 선택해야하는 불편함을 느껴 마크다운 형식으로 글 작성이 가능한 velog로 이동하려 하였습니다. 그런데 AI가 발전하면서 점점 최신 글과 인기 글이 AI로 작성한 티가 나는 글들과 광고 글들로 점령하다 보니, 자연스럽게 다른 선택지를 찾게 되었습니다.

깃허브의 장점이라면 직접 ui부터 모두 개발하곡 관리할 수 있다는 점이 장점이자 단점인데요, Claude code 결제하면서 버리는 토큰들이 많다보니 더더욱 AI를 활용하기 위해 이곳 저곳에 시도해보기 시작한 것 같습니다.

코드리뷰로 맞춤법 검사하기

ChatGPT Pro와 Claude Pro 버전을 매달 결제하고 있는 만큼 지금 AI를 지속적으로 사용하며 개발 역량을 발전시킬 필요가 있다는 생각이 들었습니다. 최근까지도 개발자로서 취업을 준비하는 입장에서 AI를 얼마만큼 호의적으로 받아들여야할지 계속 고민했었습니다. “어차피 다 대체될건데 개발해서 뭐해? 신입들이 하는 업무는 다 AI에게 맡기면 되는데? 앞으로 살아남는 개발자들은 한명한명이 팀장급의 퍼포먼스를 내는 사람들일거야.”와 같은 여러 글들을 보면서 흔들리기도 하는 것 같습니다. 또 LLM이 발전되기 이전부터 개발한 사람들은 모두 스택오버플로우나 깃허브, 옛날 블로그까지 찾아보면서 문제를 해결하던 습관과 문제를 해결했을 때의 보람참을 개발자를 희망하는 이유로 선택하는 사람들이 많았을텐데, 개발바닥 유튜브에 최근에 올라오는 영상을 보니 다 같은 생각을 하면서, 새로운 환경에서의 개발 방향성과 보상에 대한 고민을 하는 내용이 나와 모두가 같은 불안 속에서 개발을 진행한다는 것을 깨달았습니다. 그리고 저도 방향을 조금 바꾸는 것 같아요. 다양한 아이디어를 활용해서 프로젝트를 진행할 수 있거든요. 아직도 개발해고픈 아이디어가 많습니다. 내가 푼 알고리즘 시각화 사이트, 유튜브 다시보기 음악 타임라인 서비스, 방탈출 리뷰 및 예약 사이트 등등 여러 아이디어가 있어서 개발해서 직접 만들어보고자 합니다.
